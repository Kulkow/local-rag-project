# ADR 0005: Модули и направление зависимостей

## Решение

Сохраняем модульный монолит, FastAPI, SQLAlchemy и существующие таблицы.
Группируем код сначала по функциональному модулю, затем по слоям. Это уточняет
исходную раскладку ADR 0001 и AGENTS.md; новые сервисы и зависимости не нужны.

```text
src/app/
  main.py                              # composition root, lifecycle, HTTP telemetry
  api/security.py                      # общая HTTP Basic аутентификация
  core/settings.py                     # конфигурация окружения
  infrastructure/
    db/connection.py                   # общий engine/pool
    queue/tasks.py                     # Celery entry point
  modules/
    families/
      domain/entities.py               # сущности и правила родственных связей
      infrastructure/persistence.py    # таблицы и imperative ORM mappings
    operations/
      application/readiness.py         # ServiceProbe port, InspectReadiness, DTO
      infrastructure/probes.py         # PostgreSQL, Redis, HTTP adapters
      api/routes.py                    # HTTP DTO, Depends, status codes
```

`families` — текущий предметный контекст семей, людей, членств, родственных
отношений, животных и владельцев. Это одна согласованная модель из ADR 0004.
Family, Person и Pet имеют собственную идентичность; связи используют UUID,
а не загружаемый целиком граф объектов. Человек существует независимо от семьи.
PersonRelationship нормализует симметричные пары и запрещает связь с самим собой.
Уникальность, ссылки и правила удаления дополнительно обеспечиваются PostgreSQL.

SQLAlchemy использует imperative mapping обычных dataclass-сущностей. Домен не
импортирует ORM; адаптер регистрирует mappings при импорте своего модуля.
Загружаемые ORM объекты проходят ограничения БД; SQLAlchemy не вызывает
`__post_init__` при загрузке. Изменения связей после создания также должны
удовлетворять CHECK/UNIQUE БД. Для вставки связанных сущностей без ORM relationships
нужно явно flush сначала независимые сущности, затем ссылки на них.
Тип связи хранится как прежний VARCHAR(50), адаптер преобразует его в RelationshipType;
новый PostgreSQL ENUM не создаётся.
UUID задаётся вызывающим кодом для доменных объектов; Core SQL по-прежнему может
использовать серверный UUID. Временные поля новых объектов заполняет БД.

`operations` — технический модуль, не искусственно объявленный бизнес-домен.
Сценарий readiness получает именованные порты проверок, параллельно выполняет их
с тайм-аутом и возвращает результат без зависимости от HTTP. Сбой одной проверки
не скрывает остальные результаты; отмена запроса распространяется наружу.
Пустой набор проверок не считается готовностью. HTTP-слой отвечает за 200/503,
DTO и проверку администратора. Клиенты и сценарии связываются в main.py;
HTTP-клиент и engine закрываются через lifespan даже при ошибке.

## Границы

- domain зависит только от стандартной библиотеки;
- application зависит от domain своего модуля и собственных портов;
- infrastructure реализует порты и persistence, api вызывает сценарии;
- main.py связывает конкретные адаптеры; домен не читает окружение;
- семейные личности не являются учётными записями, tenant или ACL;
- межмодульные обращения должны идти через application-контракты, не через
  чужие таблицы. Сейчас таких обращений нет.

Репозитории, Unit of Work, события и application/API семей будут добавлены вместе
с реальными сценариями и авторизацией. Пустые интерфейсы и CRUD без проверки
доступа не создаём. RAG, ingestion, agents и evaluation ещё не реализованы;
будущие границы этих контекстов уточняются при реализации соответствующей фазы.
Frontend остаётся существующей Vue SPA: DDD-рефакторинг относится к backend.

## Совместимость и проверка

URL, формы ответа, Basic auth, worker command и миграции 0001/0002 сохранены.
Миграции не импортируют живую модель приложения. Смена Python-структуры не требует
новой миграции и не меняет данные. Старые внутренние импорты api.health и db.models
заменены новыми путями; все потребители в репозитории обновлены.

Архитектурный тест запрещает framework/adapter imports во внутренних слоях.
Unit-тесты покрывают readiness, отказ, тайм-аут, отмену, аутентификацию и правила
связей. PostgreSQL-тесты проверяют ограничения и round trip доменных объектов
через ORM. Общий mypy включает официальный Pydantic plugin, чтобы учитывать
создание Settings из окружения без ложных ошибок обязательных аргументов.

Дальнейшее развитие: [ADR 0006](0006-identity-family-access.md) добавляет модуль
identity и прикладной/API слой families, публичные контракты авторизации и
межмодульную связь через идентификатор членства. Описанное выше отсутствие
семейных сценариев относится к состоянию до этого расширения.
