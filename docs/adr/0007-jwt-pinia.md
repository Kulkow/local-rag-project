# ADR 0007: JWT и постоянное хранилище Pinia

## Решение

По запросу пользователя заменяем хранимые серверные сессии на подписанный JWT.
Токен и подтверждённый профиль находятся в Pinia; в localStorage сохраняется
только JWT под ключом `rag.access_token`. Cookie и sessionStorage не используются.
Это заменяет описанный в ADR 0006 механизм opaque sessions.

Добавлена зависимость PyJWT 2.10.1: библиотека выполняет стандартную подпись и
проверку JWT вместо собственной реализации JOSE. Версия зафиксирована в uv.lock.
[Документация PyJWT](https://pyjwt.readthedocs.io/en/2.10.1/api.html) описывает
проверку claims и фиксированный allowlist алгоритмов.

JWT подписывается HS256 с отдельным JWT_SECRET (не пароль администратора).
Ключ — случайное значение не короче 32 байт; в .env.example только пустое поле.
В локальном .env создан отдельный случайный ключ без вывода в логи.
Все экземпляры API должны использовать один и тот же ключ. Его замена отзывает
все выданные JWT; ключ не должен попадать в frontend build, Git или телеметрию.

Claims: sub (UUID пользователя), ver (версия отзыва), iat, nbf, exp, iss,
aud и случайный jti. Подпись, HS256, issuer `enterprise-rag`, audience `web-admin`,
обязательные поля, UUID и время проверяются. Lifetime — до 8 часов.
Права, имена и семейные данные не помещаются в payload. JWT подписан, не зашифрован.

## Проверка прав и отзыв

После проверки JWT API читает пользователя из БД по sub и ver. Проверяет активность
и актуальную роль/семейную связь. Сервер не хранит список токенов или сессий.
`users.token_version` — единственное дополнительное поле отзыва, миграция 0004.

Любое изменение пользователя увеличивает token_version. Logout также увеличивает
её атомарно, сравнивая прежнюю версию: запоздалый повторный logout старого JWT
не отзывает токены, уже выпущенные с новой версией. **Выход отзывает все JWT этого
пользователя**, включая другие устройства. Для отзыва отдельного JWT потребовался
бы отдельный denylist; в этой версии он не вводится. Refresh token отсутствует.

Таблица user_sessions из миграции 0003 больше не используется приложением.
Она сохранена вместе со своими записями, чтобы не выполнять разрушительное
удаление данных. Вход не пишет туда строки; это проверяется интеграционным тестом.
Старые opaque-токены после обновления перестают приниматься, нужен повторный вход.
SQLAlchemy AsyncSession остаётся единицей транзакции БД и не является сессией входа.

## Жизненный цикл в браузере

1. POST /auth/login возвращает access_token и профиль; Pinia сохраняет JWT в
   своём state и localStorage. Пароль не сохраняется.
2. При открытии/перезагрузке приложения Pinia берёт JWT из localStorage и вызывает
   GET /auth/me. До ответа профиль отсутствует, административные права не активны.
   Профиль из localStorage не читается и не принимается как источник прав.
3. При успехе в Pinia устанавливаются token и подтверждённый user. Запросы используют
   Authorization: Bearer. API всё равно проверяет права независимо от UI.
4. При 401 сохранённый JWT и профиль удаляются. Событие API включает исходный токен;
   запоздалый 401 для старого JWT не сбрасывает новый вход. Logout также предотвращает
   восстановление профиля запоздалым ответом /auth/me.
5. При сетевой ошибке JWT остаётся в localStorage для повторной проверки; права
   не выдаются. В UI доступна кнопка повторной проверки или новый вход.
6. Logout вызывает API и удаляет локальные данные даже при сетевом сбое. Если сервер
   недоступен, серверный отзыв не подтверждён — UI сообщает об этом. Другие устройства
   могут продолжать использовать свои JWT до отзыва/expiry.

localStorage выбран пользователем для сохранения входа между посещениями.
Он доступен JavaScript того же origin; при XSS токен может быть прочитан.
Не сохраняем пароль и профиль, не используем v-html для пользовательского контента;
внешний доступ требует TLS и дальнейшего hardening. При запрете browser storage
остаётся вход в памяти текущей вкладки, UI показывает предупреждение.
Состояние уже открытой другой вкладки перепроверяется при следующем API-запросе.

## Совместимость

Пути и DTO API сохранены; значение access_token теперь JWT. Pinia остаётся
единственным источником состояния входа для Vue-компонентов. Роли и семейная
авторизация из ADR 0006 не меняются. Basic auth для /ready/smoke сохраняется.
Throttling продолжает использовать PostgreSQL и хеш socket peer, независимо от JWT.

## Локальная проверка

Миграция 0004 применена. Ruff lint/format и strict mypy прошли. Python pytest:
35 passed, 1 skipped (Compose CLI-тест отдельно прошёл на хосте).
Frontend: 19 тестов, vue-tsc и Vite build прошли. Проверено восстановление из
localStorage, отклонённый JWT, сетевой сбой и гонки с logout/повторным входом.
API, worker и Web Admin пересобраны и имеют статус healthy.
Через Nginx подтверждены: HS256 JWT, /auth/me 200, подменённая подпись 401,
logout 204 и отказ 401 для двух ранее выданных JWT того же пользователя.
Визуальная проверка браузером недоступна; persistence проверен компонентными тестами.
