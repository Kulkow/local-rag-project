# ADR 0010: Доменные переходы метаданных документов

## Решение

Развиваем существующие `Document` и `Extraction` как неизменяемые доменные сущности.
Методы возвращают новую сущность, сохраняя идентичность и исходный объект:

- `Document.complete_upload()` и `fail_upload(code)` допустимы только из `uploading`.
- `Document.retry_upload()` допустим только из `upload_failed` и очищает ошибку.
- `Extraction.complete(page_count, character_count, artifact_key)` допустим только
  из `processing`: требуется 1–200 страниц, положительное число символов,
  непустой ключ артефакта длиной до 255 символов.
- `Extraction.fail(code)` допустим только из `processing`.
- Код ошибки должен содержать 1–50 символов.

Недопустимые переходы дают ApplicationError с кодом conflict, неверные параметры —
invalid. Публичные HTTP DTO и схема БД сохраняются. Новых зависимостей нет.

## Инфраструктура

SqlDocumentRepository и SqlExtractionRepository получают значения завершения/ошибки
из доменных методов и сохраняют их короткими транзакциями. Повтор загрузки
возвращает сущность из существующей строки с исходным created_at.

Домен проверяет состояние переданного снимка. Инфраструктура дополнительно
проверяет актуальное состояние в SQL: завершение/ошибка загрузки обновляют только
uploading; завершение/ошибка извлечения — processing с совпадающей generation.
Отсутствие строки при завершении загрузки даёт conflict. Запоздалая запись ошибки
загрузки не меняет uploaded. Lease и блокировки PostgreSQL остаются ответственностью
адаптера; методы сущностей не заменяют конкурентные SQL-условия.

MinioOriginalStorage продолжает реализовывать хранение оригиналов и артефактов.
Репозитории и object storage связываются существующим composition root; внутренних
импортов инфраструктуры из domain/application нет. Новые компоненты инфраструктуры
и миграции не требуются.

## Проверка и границы

Новые доменные тесты сначала завершились 13 ошибками отсутствующих методов,
затем прошли после реализации. Проверяются допустимые переходы, запрет повторного
завершения, неизменяемость и неверные метаданные результата.
PostgreSQL API-тест дополнен проверкой запоздалой ошибки после успешной загрузки.

Правила применяются методами переходов, не общей валидацией конструктора dataclass:
это позволяет восстановить существующие записи. Полноценный RAG-индекс,
долговечная очередь обработки и очистка объектов по-прежнему отдельные сценарии.
