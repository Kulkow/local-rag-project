# ADR 0015: Запрет одинаковых документов у одного владельца

## Решение

Одинаковые документы определяются по SHA-256 исходных байтов, уже вычисляемому
сервером. Проверка охватывает все документы одного owner_id, независимо от имени,
семьи и visibility. Другой пользователь может загрузить те же байты в доступную
семью. Семейная авторизация выполняется до проверки дубликата.

SqlDocumentRepository.reserve атомарно сериализует резервации по owner_id/checksum
через PostgreSQL transaction advisory lock. В той же транзакции проверяется наличие
документа, затем создаётся uploading. Конкурентный запрос с другим ключом получает
ApplicationError conflict (HTTP 409), до put в MinIO и создания ingestion job.
Блокировка освобождается после commit резервации, до сетевого I/O.

Прежний Idempotency-Key сохраняет поведение: завершённая загрузка возвращается
повторно, uploading даёт conflict, upload_failed допускает повтор с прежним файлом
и ключом. Новый ключ не обходит ни failed, ни uploading. Уже существующие дубли
не удаляются; повтор прежнего ключа работает и для исторических дублей.

Миграция 0010 добавляет неуникальный индекс (owner_id, checksum). Уникальное
ограничение потребовало бы разрешения исторических дублей при обновлении.
Все прикладные записи загрузки обязаны проходить через reserve: прямой SQL insert
не защищён advisory lock. Миграция не изменяет документы, объекты, ACL или индексы RAG.
Новых зависимостей и инфраструктурных компонентов нет.

Сравнение байтов не является семантическим сравнением: PDF с изменёнными метаданными
может иметь другой checksum при одинаковом извлечённом тексте. После утраты ключа
неуспешной загрузки автоматическое восстановление остаётся отдельной задачей.

## Проверка

Регрессионный PostgreSQL API-тест сначала получил 201 вместо ожидаемого 409.
Проверяются новые ключи, переименование, изменение ACL, разные семьи одного
владельца, разные владельцы, одновременные запросы, идемпотентный повтор,
повтор после ошибки хранилища и сохранение ACL. Frontend проверяет вывод ошибки
и отсутствие запуска ingestion после отказа. Live smoke использует два разных
оригинала и отдельно проверяет отказ в повторной загрузке первого.

Проверки реализации: Ruff lint/format для src/tests/migrations/scripts и strict
mypy (82 модуля) прошли. Полный pytest с реальным PostgreSQL/MinIO:
131 passed, 2 skipped. Frontend: 44 passed, TypeScript и Vite build прошли.
Миграция 0010 применена; API и worker пересобраны и достигли healthy.
Live smoke с SMOKE_MEMBER=1 прошёл: переименованный дубликат с новым ключом и ACL
получил 409; два разных оригинала прошли worker, чанкинг, Ollama embeddings и Qdrant.
Проверены keyword/vector поиск, ответ с цитатами, переиндексация, Nginx, Prometheus
и Grafana; синтетические строки и объекты очищены.
