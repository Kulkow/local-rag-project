# ADR 0016: Пакетная загрузка документов в Web Admin

## Решение

Форма принимает несколько PDF/DOCX/HTML. Пакет может суммарно превышать 10 MiB,
но каждый файл остаётся ограничен 10 MiB в браузере, Nginx, API, доменной проверке
и PostgreSQL. Один бинарный POST /documents на файл, одновременно выполняется
одна загрузка. Файлы не объединяются в multipart/архив и не читаются целиком в
JavaScript; fetch отправляет File. Произвольные файлы более 10 MiB и загрузка одного
файла по частям не входят в этот срез.

У каждого элемента свой UUID Idempotency-Key и результат: pending/uploading/saved/failed.
UI показывает имена, размеры, суммарный объём и число сохранённых оригиналов.
Ошибка валидации, сети или дубликат не останавливает следующие элементы. Кнопка
повтора отправляет только failed с прежними ключами; saved больше не отправляются.
Состояние saved фиксируется перед подтверждением очереди: ошибка подтверждения
не вызывает повторную загрузку оригинала. Статус PDF затем проверяется в списке;
успешное сохранение не означает готовность RAG. DOCX/HTML остаются без extraction.

Семья и ACL едины для выбранного пакета. Поля блокируются во время передачи;
ACL также блокируется после первой попытки до нового выбора файлов, чтобы retry
не менял область прежнего ключа. Новый выбор файлов или смена семьи сбрасывает
пакет. После перезагрузки страницы файлы/ключи не восстанавливаются — прежнее
ограничение сохранено. При смене токена оставшиеся файлы не отправляются.

Не добавляются зависимости, инфраструктура, API endpoint или миграция. Прежние
серверная авторизация каждого запроса, дедупликация и лимиты остаются действующими.
Браузерные проверки помогают пользователю, сервер остаётся источником правил.

## Проверка

Три новых теста сначала упали: multiple отсутствовал, отправлялся только первый
файл, ошибка первого прерывала пакет. Тесты проверяют пакет 12 MiB, последовательность,
разные ключи файлов, частичный отказ, retry только failed, индивидуальный лимит,
отказ подтверждения очереди и смену сессии. scripts/smoke_batch_upload.py отправляет
два HTML по 6 MiB от синтетического member через Nginx, сравнивает байты MinIO,
проверяет replay, duplicate 409 и oversized 413, затем очищает свои строки и объекты.

Результат: Docker-сборка Web Admin выполнила 49 тестов, TypeScript и Vite build —
passed; контейнер healthy. Ruff format/check и strict mypy нового smoke-скрипта —
passed. Реальный пакет >12 MiB через Nginx от member, сравнение байтов MinIO,
идемпотентность, 409 для дубля и 413 для файла больше лимита — passed.
Синтетические записи и объекты очищены. Визуальный браузерный E2E не выполнялся;
UI покрыт компонентными тестами, сетевой путь проверен отдельным smoke-скриптом.
