# ADR 0017: Компактные результаты RAG и скачивание оригиналов

Результаты /rag сгруппированы по document_id: одна карточка и одна кнопка скачивания
на оригинал. Ответ и ссылки-цитаты видны сразу, фрагменты раскрываются по нажатию;
переход по цитате раскрывает нужный фрагмент. Настройки поиска и технические сведения
(модель, времена, trace ID) остаются доступны в details. Оценка ранжирования не
называется вероятностью правильности. Текст модели и документов выводится как текст,
без v-html/исполнения HTML. Нет новых UI-зависимостей.

GET /documents/{document_id}/download требует JWT и заново проверяет видимость
private/family и актуальный доступ к семье. Ответ RAG не является разрешением на
скачивание. Чужая семья/private и отсутствующий документ возвращают 404 до чтения
MinIO. Несохранённый оригинал даёт 409; ошибки чтения/целостности — безопасный 503.
Application use case зависит только от портов; инфраструктура использует существующие
ACL-адаптеры и MinIO. Проверяются размер и SHA-256 оригинала. Размер чтения ограничен
прежними 10 MiB; для текущего лимита возвращаются ограниченные байты в памяти,
без новой инфраструктуры, presigned URLs или публичного bucket.

Response — application/octet-stream, Content-Disposition attachment с UTF-8
filename*, Cache-Control no-store и nosniff. HTML скачивается как вложение.
Клиент получает Blob через fetch с Authorization, создаёт временный object URL,
вызывает download и освобождает URL. JWT не попадает в ссылку/историю браузера.
Ошибки не сохраняются как файлы; кнопка показывает занятость и сообщение об ошибке.

Проверки: unit use case (успех, отказ ACL, незавершённая загрузка, отказ MinIO,
нарушенная целостность), PostgreSQL API (owner/member/family/private/другая семья,
анонимный доступ), MinIO E2E с точным сравнением байтов. Frontend проверяет группировку,
раскрытие цитаты, текстовую безопасность, действие скачивания и API-ошибки;
клиентский тест проверяет бинарный fetch, заголовок JWT и освобождение object URL.

Результат проверок: Ruff format/check и strict mypy (83 модуля) — passed;
pytest с реальными PostgreSQL/MinIO — 136 passed, 2 skipped. Frontend — 52 passed,
TypeScript и Vite build — passed. OpenAPI и TypeScript-схема обновлены.
API/worker/Web Admin пересобраны и healthy. Визуальный браузерный E2E не выполнялся:
браузерный инструмент в сессии недоступен. UI проверен компонентными тестами.
Live smoke SMOKE_MEMBER=1 — passed: поиск/ответ с цитатами и скачивание оригинального
PDF-источника через Nginx; байты ответа точно совпали с исходным fixture. Проверены
attachment/no-store, индексация, переиндексация и мониторинг. Синтетические записи
и объекты очищены.

Для PDF добавлена отдельная кнопка «Посмотреть оригинал». Вкладка открывается
синхронно из клика, затем оригинал запрашивается с JWT через тот же защищённый
endpoint. Вкладке передаётся Blob application/pdf без токена в URL; opener
обнуляется. При отказе доступа вкладка закрывается, при блокировке popup выводится
понятная ошибка. Object URL освобождается после закрытия вкладки, чтобы просмотр
и повторное чтение PDF не ломались из-за преждевременного revoke. Неподдерживаемые
форматы остаются доступны для скачивания. Отображение PDF зависит от настроек
встроенного просмотрщика браузера.
Проверка добавления просмотра: 54 frontend-теста, TypeScript и Vite build — passed;
покрыты открытие вкладки до fetch, PDF MIME, отсутствие opener, освобождение URL
после закрытия, ошибка доступа и блокировка popup.

Просмотр PDF также доступен в списке документов через «Открыть оригинал».
Используется существующий previewPdf и защищённый download endpoint; готовность
extraction/индексации не требуется, достаточно сохранённого PDF. Компонентные тесты
проверяют member, отсутствие extractor, ошибку доступа и скрытие кнопки для
незавершённых загрузок/других форматов.
Проверки добавления кнопки в Documents: 57 frontend-тестов, TypeScript и Vite build
прошли; API и его ACL не изменялись.
