# ADR 0022: Один Query Rewriting retry при пустой выдаче

## Решение

Для /rag/ask при пустом исходном поиске и наличии доступных indexed документов
Ollama один раз сокращает/переформулирует вопрос. Поиск повторяется в том же режиме
и с тем же top_k/threshold. Получение scopes, embedding identity и SQL ACL-проверки
повторяются; модель не выбирает семью, документы, фильтры или параметры поиска.
Ответ генерируется по исходному вопросу и найденным фрагментам. Переписанный запрос
не является evidence; качество сохранения смысла моделью не гарантируется.

Application зависит от QueryRewriter protocol, инфраструктура — OllamaQueryRewriter.
LangGraph для одного дополнительного перехода не вводится: это ограниченный use case,
не реализация полноценного agent graph. Новых зависимостей, сервисов и миграций нет.

RAG_QUERY_REWRITING=true включает retry; false сохраняет baseline. /rag/search
всегда остаётся без chat/rewrite, чтобы baseline и кнопка «Только поиск» не зависели
от LLM. Нет доступных индексов, incompatible_index/model_changed, непустая выдача
или отказ генератора не запускают rewrite. Запрос не переписывается более одного раза.

## Ограничения и ошибки

Rewriter получает только вопрос, без текста документов, инструментов и reasoning.
Системная инструкция требует сохранять язык, имена, числа, отрицание и термины;
пользовательский вопрос передаётся как untrusted JSON data. Выход ограничен JSON
с query, application проверяет тип, длину <=200, управляющие символы и отличие
от исходного вопроса. Валидация формата не доказывает смысловую эквивалентность.

Deadline rewrite — 10 секунд; общий deadline /rag/ask остаётся 80 секунд.
Пустой/невалидный ответ, provider error или rewrite timeout сохраняют no_evidence.
Отмена запроса не подавляется. Ошибки повторного поиска/авторизации распространяются
обычным путём. Повторный поиск, как и исходный, не обходит tenant/family/private ACL.

## Наблюдаемость и проверка

query_rewriting_ms и query_retry_ms включаются в API timings только при выполнении.
Prometheus rag_stage_duration_seconds получает те же фиксированные stage labels;
в Grafana общий график этапов показывает их без изменения dashboard. Текст вопроса,
rewrite и model output не логируются и не попадают в метрики. retrieval_ms включает
переформулирование и оба поиска; дочерние длительности нельзя суммировать с ним.

Unit tests проверяют keyword/vector retry, исходный вопрос генератору, ограничения,
ошибки/timeout/cancellation, обновление ACL scope, отсутствие вызова в search-only
и передачу вопроса как данных. Обычные проверки не требуют живого LLM.
Recall/faithfulness улучшения не заявляются без сравнения на golden dataset.
