# ADR 0025: Системный промпт генерации в админке

## Решение

Администратор платформы редактирует общий системный промпт RAG на `/settings`.
GET/PUT `/settings/rag` проверяют JWT и активную роль admin на сервере;
manager/member не могут читать или менять настройку. Это настройка всего
развёртывания, а не конкретной семьи. Существующие tenant/family/document ACL
применяются до передачи evidence модели и после генерации.

Миграция 0013 добавляет одну таблицу `rag_prompt_settings` с единственной
записью, текстом, версией и временем изменения. До первого сохранения используется
прежний стандартный промпт из application. Новый infrastructure-адаптер реализует
application-порт PromptStore; никаких новых зависимостей или сервисов нет.
Сохранение атомарно проверяет версию (optimistic concurrency); устаревший редактор
получает 409, включая конкурентное первое сохранение. Возврат стандартного текста
меняет черновик формы и требует обычного нажатия «Сохранить».

OllamaChat читает сохранённый текст перед каждым вызовом `answer`, закрывая DB
session до HTTP к модели. Нет process-local кэша; новые генерации видят изменения
без рестарта. Уже отправленный запрос сохраняет прежний промпт. Search-only,
rewrite и reranking не используют эту настройку. При недоступности БД ошибка
не подменяется молча стандартным промптом.

## Границы и ограничения

Промпт — буквальный текст до 8000 символов; нет форматирования шаблона, выполнения
кода или подстановки переменных. Пустой текст и NUL запрещены. Вопрос и evidence
остаются отдельным user-сообщением. JSON schema с answer/citations/
insufficient_evidence, ограничение контекста, ACL и проверка цитат сохраняются.
Изменение промпта может ухудшить ответы или увеличить отказы; качество требует
отдельной оценки. Admin может заменить инструкции, поэтому их текст сам по себе
не является границей безопасности. Не следует сохранять в промпте секреты.
Промпт не записывается в telemetry; счётчик входных токенов включает его фактический
размер по данным Ollama. История версий и аудит автора изменения в этом срезе
не реализованы; version используется для предотвращения потери правок.

## Проверки

Unit/API: доступ admin/manager/member/anonymous/inactive, валидация, конфликт,
точная передача изменённого текста модели и сохранение отдельного user-сообщения.
PostgreSQL integration: миграция, чтение default, сохранение, повторное чтение
новым экземпляром репозитория, stale update и реальная JWT-авторизация. Записи
тестов и временные изменения промпта откатываются внешней транзакцией.
Vue: загрузка, сохранение, стандартный текст, конфликт, ошибка загрузки,
запрет доступа и игнорирование запоздалого ответа после смены сессии.
