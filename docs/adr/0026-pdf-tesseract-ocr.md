# ADR 0026: Локальный OCR изображений в PDF

## Решение

Сохраняем существующий путь upload → durable job → ExtractDocument → индекс.
PdfExtractor запускает ограниченный дочерний процесс; в нём pypdf читает текст,
Poppler (`pdftoppm`) растеризует отдельные страницы, Tesseract распознаёт `rus+eng`.
Новые Python-зависимости, сервисы и миграции не требуются. Системные пакеты
`poppler-utils`, `tesseract-ocr`, `tesseract-ocr-rus`, `tesseract-ocr-eng` нужны
соответственно для рендеринга PDF и распознавания русского/английского текста;
они входят в общий базовый Docker-слой runtime и checks.

OCR применяется к страницам с изображениями (включая вложенные Form XObject и
inline images) и страницам без текста. Полная растеризация учитывает геометрию
страницы и позволяет прочитать смешанные страницы с нативным текстом и сканами.
OCR заменяет текст такой страницы, а не добавляется к нему: иначе текстовый слой
скана попал бы в индекс дважды. Цена решения — возможное ухудшение качества
нативного текста на странице с логотипом/фотографией. При пустом OCR остаётся
нативный текст. Текстовые страницы без изображений сохраняют прежнее извлечение.
Порядок чтения сложных таблиц, рукопись и качество поиска требуют отдельной оценки.

Результат использует прежний PageText/artifact contract, нормализацию, номера
страниц и ACL. Имя extractor в артефакте меняется на pages-v2 с указанием Tesseract
и языков. Никакой текст не отправляется внешнему OCR API и не пишется в логи.
Для установки языков и команд использована
[документация Tesseract](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html).

## Ограничения и отказоустойчивость

Растр ограничен длинной стороной 2400 px, обрабатывается одна страница за раз.
Изолированный процесс и его потомки имеют лимиты адресного пространства 512 MiB,
CPU 90 секунд на процесс, файла 32 MiB; core dumps отключены. OpenMP ограничен
одним потоком. Каждая внешняя команда имеет timeout 20 секунд. Общий wall timeout
PdfExtractor — 100 секунд, внутри существующего application timeout 120 секунд.
Лимиты PDF 10 MiB / 200 страниц и текста 2 MiB сохраняются.

Процессы запускаются без shell в отдельной группе. По тайм-ауту/отмене убивается
вся группа, родитель ожидает завершения parser и удаляет временный каталог.
Каталог принадлежит родителю, поэтому очистка происходит и после аварии parser.
Ошибки CLI заменяются безопасными кодами ocr_unavailable/ocr_failed/ocr_timeout;
пустой документ после OCR даёт no_text. Частичный результат не публикуется.
Текст OCR — такие же недоверенные данные, как обычный извлечённый текст.

Успешные старые артефакты автоматически не меняются: reindex перестраивает индекс
из существующей расшифровки. Неуспешное извлечение можно повторить через reindex.
Отдельные изображения, DOCX/HTML, searchable PDF на выходе и изменение языков из UI
в этот срез не входят.

Следующий срез добавляет отдельные PNG/JPEG: [ADR 0027](0027-image-tesseract-ocr.md).

## Проверка

Синтетические PDF покрывают обычный текст, пустую страницу, чистый скан и скан с
нативной подписью; распознавание проверяется реальными Poppler/Tesseract без LLM.
Unit-тесты проверяют безопасные ошибки, ограничение текста и удаление временных
файлов. Прежние тесты use case/API проверяют ACL до чтения оригинала и извлечения.
Это функциональные тесты, а не измерение качества OCR на реальных документах.

Локальная проверка 2026-11-02: Tesseract 5.3.0, Poppler 22.12.0; в worker доступны
`rus` и `eng`. Полный pytest с `TEST_OBJECT_STORAGE=1`: 261 passed, 3 skipped
(Docker CLI отсутствует в checks). Эти три Compose-теста отдельно прошли на хосте
через `python3 -m unittest discover -s tests/unit -p test_compose.py -v`.
Ruff lint/format и strict mypy (95 source files) прошли. Frontend: 88 тестов,
ESLint, TypeScript и Vite build прошли. Проверка загрузки через API с настоящими
PostgreSQL/MinIO выполнена для текстового PDF и синтетического скана; сохранённая
расшифровка и повторное извлечение проверены. Образы API/worker/Web Admin собраны
и запущены, все три сервиса healthy; API smoke подтвердил readiness зависимостей.

Основные команды: `docker compose --profile tools build checks`,
`docker compose --profile tools run --rm --no-deps -e TEST_OBJECT_STORAGE=1 checks uv run --frozen pytest -q`,
`docker compose --profile tools run --rm --no-deps web-checks sh -c 'npm test && npm run build'`,
`docker compose build api worker`, `docker compose up -d --no-deps api worker`,
`docker compose up -d --build --no-deps web-admin`.
При проверке свежего кода в checks дополнительно монтировались каталоги `src` и
`tests`; frontend аналогично использовал текущие `web-admin/src` и `web-admin/tests`.
