# ADR 0027: PNG/JPEG как документы с локальным OCR для RAG

## Решение

Изображение — самостоятельный документ: `.png`, `.jpg`, `.jpeg` принимаются существующим
бинарным POST /documents с `image/png` или `image/jpeg`. `application/octet-stream`
разрешён при подходящем расширении и содержимом. Семья, владелец, private/family,
checksum, хранение оригинала и защита от повторов используют прежний контракт.
Новых сервисов, Python-зависимостей и миграций нет. Tesseract с `rus+eng` и Poppler
уже входят в API/worker/checks Docker-образы согласно ADR 0026.

При завершении загрузки PDF/PNG/JPEG задание сохраняется в той же SQL-транзакции.
Общий реестр extractors в API и worker выбирает PdfExtractor или ImageExtractor.
Tesseract CLI используется напрямую: отдельная библиотека для декодирования картинок
в API не требуется. Распознавание возвращает одну PageText с номером 1; нормализация,
производный заголовок, артефакт, чанкинг, эмбеддинги, индекс и цитаты используют
существующий путь. В артефакте сохраняется extractor `tesseract-rus+eng/image-v1`.

Web Admin позволяет выбрать изображения вместе с PDF/DOCX/HTML, показывает очередь,
ошибки, расшифровку и фактическую готовность индекса. Оригинал изображения можно скачать
из источника в RAG Playground. Встроенный просмотр оригиналов остаётся PDF-функцией.

## Ограничения и изоляция

До сохранения проверяются расширение/MIME, сигнатура, размеры из заголовка и окончание
файла. Лимиты: 10 MiB, 20 миллионов пикселей, 12 000 пикселей по каждой стороне.
Это ограниченная проверка заголовков, а не полное доказательство корректности файла:
повреждённый файл с подходящим заголовком может завершиться ошибкой на этапе OCR.

Изображение декодируется только Tesseract/Leptonica в дочернем процессе, никогда
в обработчике HTTP. Общий IsolatedExtractor управляет временным каталогом и группой
процессов для PDF и изображений. Память ограничена 512 MiB адресного пространства,
CPU изображения — 25 секунд на процесс, размер файла — 32 MiB, core dumps отключены.
Tesseract работает с одним OpenMP-потоком и тайм-аутом 20 секунд, общий wall timeout
ImageExtractor — 30 секунд. По отмене/тайм-ауту убиваются также потомки; каталог
удаляется родителем. Текст ограничен 2 MiB, артефакт — 6 MiB.

Повреждённый ввод/превышение ресурсов/тайм-аут дают безопасные коды
`image_invalid`, `image_resource_limit`, `image_timeout` или `ocr_*`. Пустая
расшифровка — `no_text`. Неудачная обработка не публикует готовый индекс.
Частичные результаты не возвращаются. Повторы и переиндексация следуют прежним
правилам: готовый извлечённый текст используется повторно.

Прежние серверные проверки доступа применяются до чтения оригинала, артефакта и
передачи фрагментов модели; OCR-текст остаётся недоверенными данными. Содержимое
изображения и расшифровка не пишутся в телеметрию и не отправляются внешнему OCR API.
SVG/GIF/TIFF/WebP, изображения внутри DOCX/HTML, рукописные гарантии и настройка языков
из UI не входят в этот срез. Качество OCR на реальных документах требует отдельной оценки.

## Проверка

Unit-тесты используют синтетические PNG/JPEG и настоящий Tesseract, проверяют MIME,
сигнатуры, усечённые заголовки, размеры, пустой результат и тайм-аут. Общая изоляция
PDF/изображений проверяется на отмену, завершение потомков и удаление временных файлов.
API integration с PostgreSQL/MinIO проверяет PNG/JPG/JPEG, сохранность оригинала,
автоматическую очередь, расшифровку, заголовок и идемпотентность извлечения.
Frontend-тесты проверяют выбор и загрузку изображений от member и отправку в очередь.

`scripts/smoke_image_ingestion.py` проверяет реальные API/worker, русско-английскую
установку Tesseract на синтетическом английском тексте, embedding/chat-модели Ollama,
PostgreSQL/Qdrant, keyword/vector/hybrid, цитаты и запрет доступа другому участнику
и чужой семье. Созданные им записи, объекты и векторы удаляются. Это функциональная
проверка, а не измерение точности OCR или качества RAG.

Локальная проверка 2026-11-06:

- Ruff lint/format и strict mypy (100 source files) прошли. Полный pytest с
  `TEST_OBJECT_STORAGE=1`: 276 passed, 3 skipped; Compose-тесты отдельно на хосте:
  3 passed. После добавления случая PNG без pixel data отдельный прогон
  `tests/unit/test_image_extractor.py`: 11 passed.
- Frontend: 91 тест, ESLint, TypeScript и Vite build прошли. OpenAPI и TypeScript
  schema обновлены. API/worker/Web Admin пересобраны, запущены и healthy;
  `python -m app.smoke` подтвердил readiness всех зависимостей.
- Реальный image smoke прошёл: member загрузил PNG/JPG/JPEG через Nginx,
  worker выполнил OCR и индексацию, keyword/vector/hybrid нашли расшифровку,
  другой участник и чужая семья не получили приватный текст/оригинал.
  Локальная chat-модель вернула ответ с цитатами на изображения и trace ID.
  Временные данные и векторы удалены.
- Первый генерационный вызов вернул 503 по тайм-ауту около 65 секунд; после
  отдельного успешного вызова `qwen3:4b` полный smoke прошёл. Причина задержки
  первого запуска отдельно не установлена; тайм-ауты и модели приложения
  в рамках этого изменения не менялись.

Основные команды: `docker compose build api worker web-admin`,
`docker compose up -d --no-deps --wait api worker web-admin`,
`docker compose --profile tools run --rm --no-deps -e TEST_OBJECT_STORAGE=1 checks
uv run --frozen pytest -q`,
`docker compose --profile tools run --rm --no-deps web-checks`,
`python3 -m unittest discover -s tests/unit -p test_compose.py -v`.
Для проверки текущего кода в checks монтировались `src`, `tests`, `scripts`,
в web-checks — frontend `src`, `tests`, `openapi.json`. Команда image smoke с
монтированием актуального скрипта приведена в README.
