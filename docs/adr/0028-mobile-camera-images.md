# ADR 0028: Прямая загрузка снимков из мобильного клиента

## Решение

Мобильный клиент использует тот же POST /documents, что Web Admin. Снимки камеры
отправляются как JPEG/PNG вместо промежуточного PDF. Используется уже установленный
react-native-image-picker 8.3.0 с quality 0.9, maxWidth 1800 / maxHeight 2400,
assetRepresentationMode compatible, saveToPhotos/includeExtra/includeBase64 false.
MIME-алиас image/jpg нормализуется в image/jpeg.
Новые зависимости, серверы и миграции не добавляются.

Изображение копируется из временного файла picker в CacheDir/rag-photos; перед и
после копирования проверяется фактический размер. Исходный файл picker удаляется
также при ошибке. Подготовленная копия остаётся для превью и повторов, затем
удаляется при отправке, отмене или размонтировании формы. Поздний результат камеры
после ухода с экрана очищается. Кэш снимков очищается при следующем старте.

У `react-native-blob-util` 0.25.1 Android-метод `cp` вызывает callback без аргументов
при успехе, поэтому JS Promise возвращает `undefined`, хотя тип обещает `boolean`.
Клиент отклоняет явный `false` и исключения; при успешном завершении обязательно
читает размер целевой копии через `stat`, проверяет лимит и равенство размеру
исходника. Отсутствующая или неполная копия не попадает в превью и отправку.
Регрессионные тесты воспроизводят успешный callback без значения, неполную копию
и ошибку чтения целевого файла.

PrivateFiles Android больше не декодирует изображения и не создаёт PDF: остаются
UUID и очистка приватного каталога. Системный Android capture не требует добавления
собственного CAMERA/storage/gallery permission. Поддерживается только Android:
код и сборки для iOS не генерируются. Локальный шаблон ios исключён из Git;
поддержка iOS не заявляется, команды CocoaPods/Xcode не входят в проверки проекта.
Унаследованные READ_EXTERNAL_STORAGE/WRITE_EXTERNAL_STORAGE и CAMERA исключаются
из объединённого манифеста через tools:node=remove. `npm run check:apk` проверяет
реальные разрешения APK через aapt2, включая транзитивные зависимости.

Выбор файлов и проверка расширения/MIME принимают PNG/JPG/JPEG, лимит — 10 MiB;
снимки проверяются на 20 млн пикселей и 12 000 пикселей по стороне. Проверки клиента
не заменяют серверные ограничения и ACL. Изменение видимости запрещено для уже
выбранного файла; прежние JWT, семейная область и Idempotency-Key сохраняются.
После подтверждённой загрузки повторяется только планирование. Совместимость с
сервером определяется extraction-formats; отсутствие image OCR не выдаётся за
готовый индекс. Повтор обработки PNG/JPEG доступен по тем же правам, что для PDF.

OpenAPI schema клиента синхронизирована с image MIME. Устранены несовместимые с
установленными RN-типами параметры StatusBar.backgroundColor и fetch.redirect;
параметр redirect игнорировался используемым RN XMLHttpRequest fetch polyfill.
Двоичная загрузка сохраняет followRedirect=false в BlobUtil.

## Проверка и границы

Jest покрывает JPEG/PNG и MIME-алиас image/jpg, отмену и отказ камеры, неверные размеры,
фактический размер файла, очистку при сбое копирования, выбор изображений из файлов,
передачу MIME/JWT/ACL/ключа повтора, повтор очереди без повторной загрузки, старый
сервер без OCR и запрет обработки после закрытия сессии. Компонентные тесты проверяют
превью, отправку, отмену, ошибки, поздний результат камеры и права управления
документами. Нативная камера и файловая система в Jest подменены.

Tesseract, чанки и RAG выполняются сервером по ADR 0027. Клиент не оценивает точность
OCR и не выполняет распознавание на телефоне. Снимки с телефона, EXIF/поворот и
поведение конкретных камер требуют проверки на физических устройствах.
Запуск backend в Docker не устраняет необходимость Android SDK для нативной сборки.
Инструкции и сценарий ручной проверки: [mobile/README.md](../../mobile/README.md).

Перед входом клиент показывает отдельный экран адреса API и проверяет `/health`
без JWT. Короткий HTTP-адрес компьютера дополняется портом 3000 и путём `/api`
для прокси Compose; явные другие порты и пути сохраняются. Адрес хранится отдельно
от сессии в Keychain/Keystore и остаётся после выхода. При смене сервера удаляется
JWT прежнего сервера, чтобы последующий запуск не восстановил старый аккаунт.
HTTP остаётся разрешённым только в debug; release использует HTTPS.

Проверка 2026-11-06: `npm run typecheck` и 49 Jest-тестов прошли;
`npm run lint` — 0 ошибок, 23 предупреждения по стилю. Android debug APK
успешно собран для arm64-v8a/armeabi-v7a/x86/x86_64. `npm run check:apk`
сначала выявил READ_EXTERNAL_STORAGE в исходной сборке, затем прошёл после
исключения унаследованных разрешений и повторной сборки.
Реальная камера устройства и пользовательский сценарий на телефоне не проверялись.
