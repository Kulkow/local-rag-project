# ADR 0031: OpenCV → PaddleOCR → Tesseract для фотографий

## Решение

По запросу владельца проекта основным движком отдельных PNG/JPEG становится
PaddleOCR, перед ним выполняется OpenCV-подготовка. PDF сохраняет прежний путь.
Публичный upload API, ACL, оригиналы и формат страниц не меняются.

Pillow остаётся для EXIF-поворота, безопасного декодирования, прозрачности и
ограничения размеров. Далее OpenCV: grayscale, нормализация, bilateral filter,
CLAHE, ограниченное исправление наклона по согласованным линиям Hough (до 7°),
белая рамка. Бинаризация для Paddle не применяется: сохраняются градации серого.
При fallback Tesseract использует прежнюю локальную бинаризацию Sauvola.

Зафиксированы PaddleOCR 3.3.2, PaddlePaddle CPU 3.2.2, OpenCV contrib 4.10.0.84,
NumPy 1.26.4 и транзитивные зависимости. OpenCV contrib выбран потому, что его
требует PaddleX; параллельная установка разных дистрибутивов cv2 не нужна.
Docker отдельно кэширует зависимости. Два крупных wheel скачиваются восемью
HTTP-диапазонами с проверкой SHA-256 из uv.lock; затем устанавливаются по имени
через локальный find-links и проверяются финальным frozen sync. Это обход низкой
скорости одного HTTP-потока, без смены источника или версий.
Нужны libgl1/libglib2.0-0 для wheel OpenCV. Поддерживаемый runtime этого среза —
Python 3.12 в Linux x86_64 Docker; на других платформах CPU PaddlePaddle не
устанавливается и основной движок не заявляется работающим.

Модели: PP-OCRv5_mobile_det и eslav_PP-OCRv5_mobile_rec. Вторая распознаёт
восточнославянские языки; смешанный русский/английский проверяется синтетическими
тестами. Выбраны mobile-модели для локального CPU. Модельные orientation/unwarping
отключены, чтобы не загружать дополнительные модели неявно. EXIF и малый наклон
обрабатываются на этапе подготовки; произвольный поворот/перспектива не гарантируются.

## Инициализация

`make ocr-models` явно загружает две модели с официального BOS, сверяет SHA-256
из `ocr_models.py`, копирует только три разрешённых inference-файла из каждого
архива в отдельный named volume. Ограничены размер, время и пути; модель становится
доступной атомарно после проверки. Том подключён read-only в API/worker/checks.
Init-команда повторяемая, работает от root только для записи в Docker-том,
основные сервисы остаются непривилегированными. Документы не отправляются наружу.
Модели не скачиваются в обработке фото; пути задаются явно, HF работает offline.

## Переключение и ресурсы

Paddle запускается отдельным subprocess в той же группе, что парсер. Ошибка Python,
авария native-кода, тайм-аут 55s, отсутствие моделей, пустой результат или средняя
уверенность ниже 0.65 вызывают Tesseract. Смешение кириллических и латинских
букв внутри слова тоже вызывает резерв: на синтетическом примере eslav заменял
часть букв Invoice кириллическими омоглифами даже при высокой уверенности.
Автоматическая подмена букв/угадывание слов не применяется. Уверенность взвешивается по длине строк;
порог — начальная настройка, не калиброванная оценка точности. Пустой резервный
результат остаётся no_text; ошибка Tesseract не превращается в успешную расшифровку.
Превышение лимита текста не обходится fallback.

Общий wall timeout фото 100s внутри application timeout 120s. CPU: парсер 90s,
Paddle 60s; Tesseract 20s wall. Виртуальная память OCR-процессов ограничена 8 GiB
из-за mmap native-библиотек; это не оценка резидентной памяти. Cgroup API/worker —
2/3 GiB. Потоки BLAS/OpenMP и CPU Paddle ограничены одним. Исходные ограничения
10 MiB, 20 MP и 3200 px после подготовки сохраняются; временные файлы и потомки
очищаются при тайм-ауте/отмене. API запускает OCR вне event loop в дочерних процессах.

Артефакт содержит `ocr_engine` и безопасный `ocr_fallback_reason`. Имя extractor
описывает pipeline, а не маскирует резервную расшифровку под Paddle. Содержимое
и внутренние исключения не пишутся в телеметрию. Успешные старые расшифровки не
обновляются автоматически; обычная переиндексация использует прежний артефакт.

## Проверки и границы

Unit-тесты не требуют нейромоделей: отдельно проверяют основной результат,
fallback при ошибках/тайм-ауте/native crash/низкой уверенности/пустом результате,
лимиты и отказ обоих движков. Реальный Tesseract проверяется на синтетической
кириллице. `TEST_PADDLE_OCR=1` включает тесты настоящего Paddle на русском/английском,
JPEG с EXIF и небольшим наклоном и требует именно ocr_engine=paddleocr.
Это функциональные проверки, не benchmark точности на пользовательских фото.

## Локальная проверка 2026-11-12

- Ruff, форматирование и mypy: passed (104 source files).
- Unit + PostgreSQL/MinIO upload integration с TEST_OBJECT_STORAGE=1:
  306 passed, 3 skipped (Compose CLI в checks недоступен). Эти три packaging-теста
  отдельно прошли на хосте.
- Целевой прогон OCR: 27 passed, включая 4 проверки реального Paddle pipeline.
  Три русскоязычных JPEG (обычный, небольшой наклон, EXIF) прошли именно через Paddle.
  Смешанный текст проверен отдельно: корректное Invoice сохраняется основным или
  резервным движком; fallback обязан иметь обоснованную причину.
- Web Admin: Docker build, ESLint, TypeScript и 92 теста passed; мобильный TypeScript
  и 82 Jest-теста passed. Локальный Web Vitest сначала не стартовал из-за отсутствующего
  darwin Rollup-модуля; проверка выполнена в штатной Docker-сборке.
- Проверка обновлённого непривилегированного worker: русский JPEG распознан Paddle,
  затем при временно заданном отсутствующем каталоге моделей — Tesseract с причиной
  paddle_models_missing. Оригиналы/модели и настройки рабочего процесса не менялись.
- Две модели и два крупных wheel проверены фактическими SHA-256, сборка runtime прошла.

Новые фотографии пользователя и рукописный текст в этих проверках не использовались;
результаты не являются измерением качества OCR на реальных снимках.
