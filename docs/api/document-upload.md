# Загрузка файлов для RAG

## Запуск и Web Admin

```sh
docker compose build api migrate web-admin
make migrate
docker compose up -d api worker web-admin
```

Новых секретов не требуется: Docker local использует уже настроенный MinIO.
Откройте http://localhost:3000/documents и войдите существующей учётной записью.

1. Выберите семью. Если семьи ещё нет, администратор создаёт её на странице «Семьи».
2. Любой авторизованный пользователь выбирает PDF/DOCX/HTML размером до 10 MiB.
3. Выберите доступ: личный (владелец + администратор) или для выбранной семьи.
4. Нажмите «Загрузить файл». При сетевой ошибке можно повторить отправку того же
   выбранного файла: повтор не создаёт второй документ.
5. Список показывает имя, размер, доступ, состояние, ID и checksum.

**uploaded означает только сохранённый оригинал.** Документ ещё не индексирован
и не участвует в RAG-поиске. Не требуются модели Ollama или запущенный LLM.
Участник с ролью member может загружать документы в доступную семью и видеть
свои private и доступные family документы.
Содержимое документа в браузере не исполняется и не отображается как HTML.

## REST API

Нужен действующий JWT: Authorization: Bearer TOKEN.

### POST /documents

Query: family_id (UUID), filename (до 255 символов), visibility (private/family,
по умолчанию private). Обязателен Idempotency-Key: UUID.
Content-Type: application/pdf, DOCX MIME, text/html либо application/octet-stream
при известном расширении. Тело — бинарные байты файла, **не multipart и не JSON**.
Имя, расширение, MIME и содержимое проверяются сервером.

```sh
curl -i 'http://localhost:8000/documents?family_id=FAMILY_UUID&filename=guide.pdf&visibility=private' \
  -H 'Authorization: Bearer YOUR_JWT' \
  -H 'Idempotency-Key: YOUR_UPLOAD_UUID' \
  -H 'Content-Type: application/pdf' \
  --data-binary @guide.pdf
```

Возвращает 201, DocumentView: id, family_id, owner_id, filename, content_type,
size_bytes, checksum (SHA-256), visibility, status, error_code, created_at.
Object key/credentials/private URL в ответ не входят. X-Request-ID и Server-Timing
сохраняются. Повтор с тем же ключом возвращает прежний документ, если файл и ACL
не изменились. Для нового файла используйте новый UUID.

### GET /documents?family_id=UUID&offset=0&limit=20

Список метаданных доступных документов. Максимум 100 записей за запрос. Глобальный
admin видит все документы выбранной семьи, менеджер/участник — family и собственные
private. Чужая/отсутствующая семья даёт 404, а не пустой неограниченный список.

### Ошибки и состояния

- 401: JWT не принят; 403: недостаточно прав для управления чужой обработкой; 404: семья недоступна;
- 409: другой файл/область с прежним ключом либо загрузка уже выполняется;
- 413: больше 10 MiB; 415: неподдерживаемый/несовпадающий тип;
- 422: неверные поля, пустой файл или небезопасное имя;
- 408: истёк срок чтения тела; 429: слоты загрузки заняты;
- 503: сбой хранения/завершения операции, состояние можно проверить в списке.

uploading — зарезервирована операция, uploaded — оригинал сохранён,
upload_failed — неуспешная операция. cleanup_required означает, что администратору
нужно проверить и при необходимости удалить объект в MinIO. Повтор failed с тем же
файлом/ключом поддерживается. Автовосстановления uploading после падения процесса нет.
Ключ повторной попытки не сохраняется после перезагрузки Web-страницы.

## Проверка

```sh
make check
# Дополнительные integration/E2E тесты с реальным локальным MinIO:
docker compose --profile tools run --rm -e TEST_OBJECT_STORAGE=1 checks uv run --frozen pytest -q tests/integration/test_documents.py
```

Для live MinIO тестов сервисы postgres/minio должны быть запущены, а БД мигрирована.
Обычные unit-тесты не используют модель/MinIO. PostgreSQL-тест с подменённым storage
запускается штатно; два live MinIO теста включаются явным TEST_OBJECT_STORAGE=1.

Архитектура, TDD red/green и ограничения: [ADR 0008](../adr/0008-document-upload.md).

Модель хранения, поля и ограничения БД: [метаданные документов](../architecture/document-metadata.md).

PDF теперь получает задание на извлечение текста атомарно при успешном upload.
Статус и повторный запуск: [API очереди обработки](processing-queue.md).
Очередь ещё не создаёт RAG-индекс.

## Где находится форма загрузки

Откройте http://localhost:3000/documents#upload или пункт «Загрузка документов»
в меню. Из RAG Playground доступна ссылка «Загрузить документ».
Нужен вход с любой ролью (admin/manager/member) и выбранная доступная семья.

Форма больше не исчезает при пустом списке семей: до выбора семьи поля отключены
с пояснением. Admin может создать семью на /families, вернуться и нажать
«Обновить список семей». Manager при пустом списке обращается к администратору
для проверки связи с участником семьи. Member также видит форму и может загружать документы. Права управления семьёй
при этом не расширяются.

Ошибка /documents/extraction-formats не блокирует получение списка семей и
сохранение оригинала. В этом случае отображается отдельное предупреждение
о недоступности сведений автоматической обработки. Обновите страницу для их
повторного получения. Сервер самостоятельно планирует PDF-processing при upload.

Политика загрузки всеми авторизованными пользователями: [ADR 0014](../adr/0014-member-document-upload.md).

Для проверки полного pipeline от роли member используйте синтетический smoke
после запуска API, worker, Web Admin, Ollama и monitoring:

```sh
docker compose --profile tools run --rm --no-deps -e SMOKE_MEMBER=1 \
  -v "$PWD/src:/app/src:ro" -v "$PWD/scripts:/app/scripts:ro" checks \
  uv run --frozen python scripts/smoke_processing_queue.py
```

Созданные тестом пользователь/member, семья, документы, артефакты и векторы
удаляются после проверки. Реальные учётные записи и роли не меняются.

## Защита от дубликатов

Новый ключ загрузки не позволяет повторно загрузить одинаковые байты одному
пользователю: API вернёт **409 Conflict** до записи второго оригинала и постановки
в очередь. Проверка использует SHA-256, не зависит от имени файла, семьи или
видимости и защищена от конкурентных запросов. Другой пользователь может загрузить
тот же файл. Различающиеся байты (даже при одинаковом тексте) считаются разными файлами.

Повтор запроса с прежним Idempotency-Key остаётся идемпотентным. Для upload_failed
используйте прежний ключ и файл; новый ключ будет отклонён. Старые дубликаты
не удаляются. Подробнее: [ADR 0015](../adr/0015-document-content-deduplication.md).

## Несколько файлов и пакет больше 10 MiB

В форме можно выбрать несколько файлов (Ctrl/Cmd/Shift в диалоге выбора).
Кнопка «Загрузить файлы» отправляет их последовательно, по отдельному запросу на
каждый. Суммарный объём пакета может превышать 10 MiB; **один файл — до 10 MiB**.
Отображаются общий размер, число сохранённых файлов и результат каждого элемента.

При частичной ошибке остальные файлы продолжают загружаться. «Повторить неуспешные»
использует прежние ключи только для файлов с ошибкой загрузки. Уже сохранённые
оригиналы повторно не передаются, даже если подтверждение очереди не удалось.
Проверяйте обработку PDF в списке документов. Пока есть результаты попыток, ACL
пакета фиксирован; новый выбор файлов сбрасывает результаты и ключи. Перезагрузка
страницы также сбрасывает пакет.

Проверка реального пакета >12 MiB через Nginx и MinIO без запуска модели:

```sh
docker compose --profile tools run --rm --no-deps \
  -v "$PWD/src:/app/src:ro" -v "$PWD/scripts:/app/scripts:ro" \
  checks uv run --frozen python scripts/smoke_batch_upload.py
```

Нужны работающие API/Web Admin/PostgreSQL/MinIO с применёнными миграциями.
Тест создаёт временного member и семью, удаляет свои документы и объекты после проверки.
[Решение и границы](../adr/0016-batch-document-upload.md).

## Скачивание оригинала

`GET /documents/{document_id}/download` с `Authorization: Bearer TOKEN` возвращает
бинарный оригинал как вложение. В /rag кнопка «Скачать файл» доступна в карточке
каждого найденного документа. Проверяется актуальная видимость документа и доступ
к семье, независимо от прежнего результата RAG. Анонимный запрос: 401; недоступный
документ: 404; незавершённая загрузка: 409; ошибка чтения/целостности: 503.
Имена UTF-8 передаются в Content-Disposition; ответ не кэшируется.

Для PDF рядом со скачиванием в `/rag` доступно «Посмотреть оригинал»: документ
открывается в новой вкладке во встроенном PDF-просмотрщике браузера. Применяются
те же проверки доступа; JWT не передаётся в URL. Если браузер блокирует вкладку,
разрешите её открытие для этого сайта. При настройке браузера «всегда скачивать PDF»
файл может скачиваться вместо встроенного просмотра.
