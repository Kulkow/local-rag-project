# RAG Mobile

**Поддерживаемая платформа — только Android. iOS не разрабатывается и не собирается.**
При работе с проектом не генерировать код и сборки для iOS, не запускать CocoaPods
и Xcode. Локальный каталог `ios` может остаться от шаблона React Native;
он исключён из Git вместе с неиспользуемыми Ruby/CocoaPods-настройками.

React Native клиент для входа в существующую RAG-платформу, выбора семьи, загрузки
документов и съёмки камерой. Backend запускается обычным Docker Compose из корня
репозитория; OCR и индексация выполняются сервером, а не телефоном.

## Подключение к API по Wi-Fi

При первом запуске сначала открывается экран адреса API. Подключите телефон и
компьютер с сервером к одной Wi-Fi сети, введите `http://192.168.1.20` (замените IP
на адрес компьютера) и нажмите «Подключиться». Для HTTP-адреса без порта и пути
клиент добавит `:3000/api`; для `http://IP:3000` добавит `/api`. Полный адрес с другим
портом или путём сохраняется без подстановок. HTTPS-адрес указывайте полностью.

Клиент проверяет `/health` без учётных данных и при успехе открывает логин и пароль.
При ошибке адрес можно исправить и повторить проверку. Проверка подтверждает
доступность API, но не готовность OCR, индексации или моделей. HTTP поддерживается
в debug-сборке; release требует HTTPS.

Адрес сохраняется отдельно от JWT в защищённом хранилище Android, в том числе до
первого входа и после выхода. На форме входа есть кнопка «Изменить адрес API».
Действующая сохранённая сессия восстанавливается автоматически; при недоступном
сервере снова показывается экран с редактируемым сохранённым адресом.
Проверка доступа к серверу с телефона и настройка Compose описаны ниже.

## Загрузка снимка

1. Войдите и выберите доступную семью.
2. Откройте «Загрузить», выберите «Личный» или «Для семьи».
3. Нажмите «Сфотографировать документ», подтвердите снимок и проверьте превью.
4. Нажмите «Отправить в RAG». Снимок отправляется бинарным JPEG/PNG с JWT и
   постоянным Idempotency-Key. Преобразования в PDF больше нет.
5. На вкладке «Документы» обновляйте состояния до «Доступен для поиска».
   Поиск, ответы и просмотр расшифровки доступны в Web Admin / RAG Playground.

«Выбрать файл» принимает PDF, DOCX, HTML, PNG, JPG и JPEG. Лимит — 10 MiB на файл.
Камера запрашивает изображение до 1800 × 2400 px с quality 0.9. Проверяются
фактический размер файла и размеры снимка (не более 20 Мп и 12 000 px по стороне);
сервер независимо проверяет сигнатуру, MIME, размеры и права доступа.

Приложение не добавляет снимок в галерею. Рабочая копия хранится в приватном кэше,
удаляется после отправки, отмены, смены семьи или выхода; кэш снимков также очищается
при следующем запуске. Во время временного перехода в приложение камеры выбор
сохраняется. Отмена камеры сохраняет предыдущий выбранный файл.

После ошибки сети повтор использует тот же ключ. Если оригинал уже сохранён,
повторяется только проверка форматов / постановка в очередь, без второй загрузки.
Сервер без image OCR может сохранить оригинал: клиент явно сообщает, что он ещё
не индексируется. PDF и PNG/JPEG можно повторно поставить в очередь после ошибки.
DOCX/HTML пока сохраняются без автоматической индексации.

### Ошибка «Не удалось сохранить временный снимок»

Эта ошибка возникает на телефоне при подготовке копии фото, до HTTP-загрузки,
поэтому соответствующего запроса не будет в логах API/worker. В клиенте исправлена
проверка результата `react-native-blob-util.fs.cp`: Android возвращает `undefined`
при успешном копировании, а не `true`. Теперь клиент проверяет доступность и размер
готовой копии; неполные файлы отклоняются и очищаются.

Для применения исправления в debug запустите Metro из текущего каталога `mobile`
и выполните **Reload**, затем сделайте новый снимок. Порядок подключения и
пересборки описан в разделе [«Пересборка после правок»](#пересборка-после-правок).

## Сборка

Для нативного клиента нужны Node.js >=22.11, Android SDK и React Native
окружение. Версии JS-зависимостей зафиксированы в package-lock.json. Для серверных
компонентов по-прежнему достаточно Docker / Compose и настроенной Ollama.

Связка инструментов текущего проекта:

| Инструмент | Версия |
| --- | --- |
| React Native | 0.88.1 |
| Android Gradle Plugin | 9.2.1 (из React Native Gradle Plugin) |
| Gradle Wrapper | 9.4.1 |
| Kotlin Gradle Plugin | 2.2.0 |
| Android Studio | Panda 4 / 2025.3.4 или новее с поддержкой AGP 9.2 |
| compileSdk / targetSdk | 37 / 36 |
| Android Build Tools | 37.0.0 |
| NDK | 27.1.12297006 |

Совместимость IDE, AGP и Gradle сверяется по
[официальной таблице Android](https://developer.android.com/build/releases/about-agp).
Android Studio 2022.2.1 для этой связки не подходит. Для сборки используйте
проектный `./gradlew`; автоматически менять версии AGP/Gradle при открытии проекта
не требуется. Gradle JDK выбирайте совместимый с Gradle 9.4.1; CLI-сборка локально
проверена с OpenJDK 26.0.1.

Из каталога mobile:

```sh
npm ci
npm start
# В другом терминале:
npm run android
```

Android использует системное приложение камеры без собственных разрешений
CAMERA/storage/gallery. Модуль PrivateFiles создаёт UUID и очищает приватный кэш.
После изменения нативного кода требуется пересобрать приложение.

## Пересборка после правок

Для повседневной разработки используйте **debug**. Обновлять Android Studio после
каждой правки не нужно. Выберите действие по изменённым файлам:

| Что изменилось | Что сделать |
| --- | --- |
| Интерфейс и логика в `App.tsx`, `src/**/*.ts`, `src/**/*.tsx` | Оставить Metro запущенным и выполнить Reload в меню разработчика приложения. Пересборка debug APK не требуется. |
| Зависимости в `package.json` / `package-lock.json` | Выполнить `npm ci` из `mobile`, перезапустить Metro; при добавлении или изменении нативного модуля пересобрать и установить приложение. |
| Kotlin/Java, `AndroidManifest.xml`, Gradle, нативные ресурсы в `android` | Пересобрать и установить приложение через Android Studio или CLI по инструкции ниже. |
| Настройки Metro или Babel | Остановить Metro через Ctrl+C и запустить заново; если остался старый интерфейс, использовать `npm start -- --host 0.0.0.0 --reset-cache`. |

### Через Android Studio

1. В терминале из корня репозитория запустите Metro и оставьте его работающим:

   ```sh
   cd mobile
   npm start -- --host 0.0.0.0
   ```

2. Откройте проект `mobile/android` в Android Studio. При изменениях Gradle
   выполните **Sync Project with Gradle Files**.
3. В **Build Variants** выберите `debug` для модуля `app`, затем выберите телефон
   или запущенный эмулятор и нажмите **Run ▶**. Android Studio пересоберёт,
   установит и запустит приложение. Для USB-телефона включите USB debugging и
   подтвердите разрешение подключения на устройстве.
4. Настройте доступ к Metro и API по Wi-Fi или USB, как описано ниже. После
   следующих правок только TypeScript/JavaScript достаточно **Reload**.

### Через терминал

При уже запущенном Metro откройте второй терминал и выполните из корня репозитория:

```sh
cd mobile
npm run android
```

Команда собирает, устанавливает и запускает debug-приложение на подключённом
устройстве или эмуляторе. Если нужен APK для ручной установки, вместо неё выполните
из корня репозитория:

```sh
cd mobile/android
./gradlew :app:assembleDebug --no-daemon
cd ..
npm run check:apk
adb devices
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

После установки откройте RAG Mobile на телефоне. При нескольких устройствах
используйте `adb -s SERIAL install -r ...`, подставив SERIAL из `adb devices`.
Флаг `-r` обновляет приложение с сохранением его данных. APK находится в
`mobile/android/app/build/outputs/apk/debug/app-debug.apk` от корня репозитория.
Если все Gradle-зависимости уже загружены, можно добавить `--offline` к команде
сборки. Обычная пересборка не требует `clean` или удаления приложения.

**Debug APK загружает JavaScript из Metro:** установка APK сама по себе не
обеспечивает работу без компьютера. В release JavaScript включён в APK, поэтому
после любых правок, включая TypeScript, требуется пересборка и установка release.
Для API в release нужен HTTPS; текущая release-конфигурация использует debug-ключ
подписи и не предназначена для публикации в магазине.

### Телефон по Wi-Fi: Metro и API

У приложения два отдельных адреса. Например, если IP компьютера `192.168.1.20`:

| Назначение | Адрес на телефоне |
| --- | --- |
| Metro — загрузка интерфейса debug-приложения | `192.168.1.20:8081` в настройках разработчика, без `http://` и `/api` |
| Backend — вход, документы и загрузка | `http://192.168.1.20:3000/api` на первом экране приложения |

Замените пример на текущий Wi-Fi IP компьютера. Телефон и компьютер должны быть
в одной сети; Metro запускайте с `--host 0.0.0.0`, как показано выше.
Откройте меню разработчика приложения встряхиванием телефона, затем **Dev Settings →
Debug server host & port for device**, введите `IP-компьютера:8081`, вернитесь
назад и нажмите **Reload**. Для эмулятора меню также открывается через Ctrl+M
(Cmd+M на macOS).

Если ошибка указывает на `localhost:8081`, исправьте адрес **Metro** в этих
настройках: первый экран с полем API появится после загрузки JavaScript.
Если интерфейс уже открыт, но не проходит «Подключиться», проверьте **адрес API**
и откройте `http://IP-компьютера:3000/api/health` в браузере телефона.
При сетевой ошибке проверьте firewall для TCP 8081/3000 и изоляцию Wi-Fi клиентов.
Адрес `http://localhost:8081` в терминале Metro не означает, что его нужно вводить
в поле API на телефоне. Metro используйте в доверенной локальной сети.

### Телефон по USB

При подключённом телефоне и работающем Metro можно перенаправить оба порта:

```sh
adb reverse tcp:8081 tcp:8081
adb reverse tcp:3000 tcp:3000
```

В **Debug server host & port for device** укажите `localhost:8081`, выполните
**Reload**, а в поле API введите `http://127.0.0.1:3000/api`. Эти loopback-адреса
работают на телефоне благодаря `adb reverse`; без него для Wi-Fi нужен IP
компьютера. После переподключения устройства перенаправление может понадобиться
выполнить заново.

### Ошибка IDE: Unable to load class org.gradle.util.VersionNumber

Если синхронизация Android Studio падает с этой ошибкой, а стек содержит
`com.android.ide.gradle.model.builder.AndroidStudioToolingPlugin`, проверьте
версию IDE через About Android Studio. Локально ошибка подтверждена для
Android Studio 2022.2.1: её tooling-плагин обращается к классу, отсутствующему
в Gradle 9.4.1. Ошибка возникает ещё при импорте проекта и не связана с камерой.

1. Установите Android Studio Panda 4 / 2025.3.4 или более новую совместимую версию
   с [официального сайта](https://developer.android.com/studio).
2. Откройте каталог `mobile/android` в новой IDE.
3. В Settings → Build, Execution, Deployment → Build Tools → Gradle используйте
   Gradle Wrapper проекта и совместимый Gradle JDK, затем выполните Sync Project.
4. Для отдельной проверки конфигурации выполните из `mobile/android`:
   `./gradlew help --offline --no-daemon` (после первоначальной загрузки зависимостей).

Понижение только Gradle ради старой IDE нарушит требование AGP 9.2 к Gradle 9.4.1.
Удалять SDK, глобальный кэш Gradle или добавлять копию VersionNumber в приложение
для исправления этого случая не требуется.

В поле адреса API укажите:

- Android Emulator: http://10.0.2.2:3000/api;
- физический телефон в той же Wi-Fi сети (debug): http://IP-компьютера:3000/api;
- release-сборка: доступный телефону HTTPS-адрес API / прокси.

HTTP разрешён клиентом только в debug-сборке. Для Android по USB можно выполнить
`adb reverse tcp:3000 tcp:3000` и указать http://127.0.0.1:3000/api. Учитывайте, что
прокси Compose на порту 3000 теперь слушает все интерфейсы хоста.
После обновления выполните из корня `docker compose up -d --no-deps web-admin`.
Если в `.env` задан `WEB_BIND_ADDRESS=127.0.0.1`, замените его на `0.0.0.0`
или LAN-IP компьютера и повторите команду. Прямой порт API 8000 остаётся локальным.

LAN-IP на macOS можно узнать через `ipconfig getifaddr en0` (для другого Wi-Fi
интерфейса используйте его имя). Например, для IP `192.168.1.20` в приложении
нужен адрес `http://192.168.1.20:3000/api`. Сначала откройте на телефоне
`http://192.168.1.20:3000/api/health`: должен вернуться JSON со статусом.
Если адрес недоступен, проверьте firewall для TCP 3000 и изоляцию клиентов/гостевую
сеть на роутере. `localhost` на телефоне означает сам телефон.
Не публикуйте БД и MinIO; локальный HTTP используйте только в доверенной сети.

JWT хранится в Keychain/Keystore; аккаунты, семьи и ACL проверяет сервер.
Обычные учётные записи и пароли из Web Admin подходят и здесь. Выход отзывает
сессии пользователя на сервере, включая Web Admin.

## Проверки

```sh
npm run typecheck
npm run lint
npm test -- --runInBand
cd android
./gradlew :app:assembleDebug
cd ..
npm run check:apk
```

Jest проверяет реальные функции подготовки файлов с подменой камеры/файловой
системы, отправку MIME/JWT/ACL и идемпотентность, ошибки разрешений и очереди,
очистку файлов, превью и запрет чужих управляющих действий. Это не проверка
физической камеры. Watchman для Jest отключён; Metro может использовать его отдельно.
`check:apk` проверяет разрешения именно собранного APK, включая объединённые
манифесты библиотек: CAMERA и широкий доступ к файлам/медиа должны отсутствовать.
Проверка использует aapt2 из Android Build Tools 37.0.0, указанного в проекте.

Для ручной проверки используйте синтетический печатный лист с уникальной фразой:
снимок → превью → отправка → готовый индекс → поиск этой фразы в RAG Playground.
Проверьте отказ в доступе к камере, отмену, повтор после отключения сети и запрет
чтения private-документа другим участником. Реальную съёмку проверяйте на
Android-устройстве: Jest подменяет камеру и не подтверждает работу оборудования.

Локальная проверка 2026-11-06: TypeScript прошёл, 49 Jest-тестов прошли,
ESLint — 0 ошибок и 23 предупреждения по стилю. Android debug APK успешно собран
командой `./gradlew :app:assembleDebug --offline --no-daemon`; `npm run check:apk`
подтвердил отсутствие CAMERA и широких разрешений на файлы/медиа. Файл сборки:
`android/app/build/outputs/apk/debug/app-debug.apk`. Для debug APK нужен Metro.
Съёмка физической камерой в эту проверку не входила. iOS исключён из дальнейшей
разработки, генерации и сборки по требованию владельца проекта.
